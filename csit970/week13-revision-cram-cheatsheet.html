Wk1 · Analysis Framework & Security Concepts

Q: privacy vs confidentiality? (not crypto) privacy = secrecy for the individual’s benefit = a right/control (extends to family, not legal person); confidentiality = secrecy for the organisation’s benefit = a duty to protect others’ secrets; secrecy = the mechanism’s effect. Hospital: patient has privacy, staff owe confidentiality.

Q: trusted vs trustworthy? Can a system be trusted but not trustworthy? trusted = its failure would break the security policy (we’ve leaned on it); trustworthy = won’t fail (actually reliable). Trusted but not trustworthy = most dangerous (e.g. an intelligence officer entrusted with secrets who plans to defect).

Q: principal vs role? Give an example. principal = any entity in the system (person/device/channel/crypto key/group — widest); role = a function held by different people in turn (Tutor / society president).

Also: PMAI framework = Policy→Mechanism→Assurance→Incentive, ≠ CIA (common trap). authenticity = integrity + genuineness; integrity is verifiable by anyone (hash), authenticity needs a key (HMAC/signature). Spec chain security policy→security target→protection profile.

Wk2 · Cyber Threats

Q: dropper mechanism of virus/Trojan? dropper = first stage of staged delivery, carries and releases the next-stage payload itself; vs downloader = fetches it from the internet, vs payload = does the actual work; Trojan = disguise as legit software. Dropper carries · downloader fetches · payload acts.

Q: what is a botnet, how used in cybercrime? botnet = network of compromised devices (incl. IoT) controlled remotely via C2 (command-and-control). Lifecycle: infection→C2→uses. Uses: DDoS/spam-phishing/credential theft/anonymising proxy for crime/cryptomining. Hard to kill: Conficker (DGA), Mirai (IoT default passwords).

Q: ransomware vs hacktivism (objective/method/target)?

Ransomware Hacktivism
Objective financial (extort) political/ideological
Method encrypt + threaten leak (double extortion), RaaS DoS/defacement/hack-and-leak/doxxing
Target public sector, healthcare government/public-facing orgs

Q: role of mass surveillance — why both protective and a privacy threat? Dual-use: protective = intelligence/counter-terror/crime tracking (with XKeyScore); threat = backbone collection (PRISM/Tempora/Muscular) + weakening crypto (Bullrun/Dual_EC_DRBG) + mercenary spyware. Crypto-currency is pseudonymous ≠ anonymous (traceable).

Wk3 · Cryptography

Q: symmetric vs asymmetric + one example each? symmetric = same shared secret key (must pre-share, fast; e.g. AES); asymmetric = key pair (public encrypts / private decrypts, no pre-share, solves key distribution, slow; e.g. RSA).

Q: what is a side-channel attack + one example? Attacks the implementation’s physical leakage, not the algorithm (timing/power/EM/sound), it’s passive. E.g. RSA decryption power analysis — square-and-multiply, a key-bit = 1 draws extra power → read the private key bit-by-bit.

Must know: hash (integrity) → MAC (+authentication, shared key) → digital signature (+non-repudiation, sign with private / verify with public). PKI/CA binds identity↔︎public key, defeats MITM. RSA security = integer factorisation; quantum threat Shor’s algorithm → post-quantum. MD5/SHA-1 broken. Key strength = real entropy, not output length.

Wk4 · Network Attack & Defence

Q: disadvantage of DoH? Encrypting DNS boosts privacy but reduces network visibility → defenders can’t easily monitor/filter malware or C2 domains, or spot DNS hijacking.

Q: how can attackers exploit BGP? BGP is built on trust with no strong validation → BGP hijacking: falsely advertise an IP prefix you don’t own → bogus route spreads → traffic redirected (fake-site phishing / blackholing DoS / eavesdropping). Defence RPKI + ROA (signatures).

Q: what problem does DNSSEC solve, how? DNS records can be forged (cache poisoning/pharming) → add digital signatures to records → integrity + authenticity (no confidentiality, no DDoS protection, can even enable amplification).

Q: role of NAT in security, why not a true security mechanism? NAT = many devices share one public IP (to fight IPv4 exhaustion). Not a security control: no encryption/authentication; it actually makes attribution harder (logs show only the shared IP).

Q: how does a VPN/IPsec ensure confidentiality & integrity? IP-layer tunnel; IKE (/Diffie–Hellman) sets up the shared key + SA; encryption → confidentiality, authentication → integrity/authenticity.

Contrasts: DNS hijack edits the address-book (→I) vs BGP hijack edits the road-map (→A); DDoS→A. TLS = handshake (authenticate + DH key) → record (symmetric encryption). DKIM = sign with the sender domain’s DNS public key.

Wk5 · Usability

Q: what does generating passwords from mnemonic phrases mean? Pick a memorable, hard-to-guess sentence → take first letters of each word + digits/case → looks random yet memorable (passphrase, Yan 2004).

Q: what is the bystander effect, how does it affect security behaviour? bystander effect = diffusion of responsibility → everyone assumes someone else will report → no one reports (Kitty Genovese). Fix: assign clear reporting responsibility + easy channels.

Q: what is social engineering, why often more successful than technical attacks? social engineering = psychological manipulation of people (not tech). More successful because it bypasses technical controls + exploits Cialdini’s principles (authority/scarcity…) + our anti-deception instincts evolved for face-to-face (fail on email).

Q: how does poor personal OPSEC lead to org breaches? Social-media exposure → guess security questions / craft spear-phishing; password reuse; insecure BYOD. Need a culture of compliance.

Q: common weaknesses in password recovery? security questions (guessable) / email recovery (single point of failure) / SMS (SIM swap) + help-desk social engineering. Recovery = the weakest link.

Q: security risk of a password manager? All passwords behind one master password = single point of failure (phished → all stolen); but don’t block them (users pick weaker passwords otherwise).

Also: three human errors = slips/lapses · mistakes · misconceptions; store hash + salt (≠ encryption); CAPTCHA = a hard AI problem (beaten by AI + fairness flaws).

Wk7 · Cybersecurity Standards

Q: purpose of data classification + common levels? Classify by sensitivity to decide how strong a control is needed (not everything needs equal protection — saves cost). Public→Internal→Confidential→Restricted (Restricted must be encrypted).

Q: five core functions of NIST CSF? Identify→Protect→Detect→Respond→Recover (security is not just prevention).

Q: essential steps of the risk management process? Identify→Analyze→Evaluate (risk assessment)→Treat→Monitor&Review = a continuous cycle (not one-off).

Must know: Essential Eight, three groups = stop malicious code (application control / Office macros / user app hardening) + limit attackers (restrict admin / MFA) + reduce exposure & recover (patch apps / patch OS / backups); maturity 0–3. ISO27001 = standard for an ISMS, goal CIA + risk-based + continuous improvement. need-to-know; MFA factors know/have/are; policy/control/standard/framework.

Wk9 · Privacy

Q: do the MPC calculation (as in assignment/class) additive secret sharing, no TTP, average salary (70/60/80): ① each splits value into 3 random shares (sum = true value, may be negative) → ② keep one, send the other two → ③ each publishes the sum of shares it holds → ④ add the three sums ÷ count. E.g. published sums 100/85/25 → (100+85+25)/3 = 210/3 = 70K ✓. MPC ≠ zero leakage (you learn “who’s higher/lower”, not exact values). Age version is identical (25/30/35→30).

Q: how does HE keep data private on clouds/ML? Homomorphic Encryption = compute on ciphertext, E(M1+M2)=E(M1)+E(M2)E(M_1{+}M_2)=E(M_1){+}E(M_2); encrypt locally → send to cloud → cloud computes on ciphertext (never decrypts) → returns ciphertext → decrypt locally. Both input AND result stay encrypted; downside: slow.

Q: what is Differential Privacy, how does it protect individuals? DP defeats a differential attack (adding/removing one person changes the output and leaks their presence) by adding noise (scale = 1/ε): Pr[M(D)∈S]≤eεPr[M(D′)∈S]\Pr[M(D)\in S]\le e^{\varepsilon}\Pr[M(D')\in S] (D, D’ differ by one record). smaller ε → more noise → more privacy, less accuracy (privacy–accuracy trade-off).

Q: concept of SMPC, how it enables private collaboration? SMPC: parties compute z=f(x1..xn)z=f(x_1..x_n) and learn only the output z; f is public, no TTP, via secret sharing. E.g. hospitals computing joint stats; Federated Learning with secure aggregation.

Q: why is ML important for security, supervised vs unsupervised? ML auto-learns patterns to detect threats (malware classification/intrusion/phishing) and adapt to new attacks. supervised = labelled → classify known threats; unsupervised = unlabelled → anomaly detection, finds zero-day (higher false positives).

Q: privacy concerns of location tracking + mitigations? Builds a profiling picture; location trading. Mitigate: data minimisation/coarsening/anonymisation+DP/consent/timely deletion.

Q: GDPR’s data minimisation? Collect only the minimum personal data necessary for the purpose (adequate/relevant/limited) → less breach exposure.

Q: purpose of the APPs + name three? Australian Privacy Act 1988, 13 APPs, principle-based + technology neutral. E.g. APP1 transparent management / APP6 use & disclosure / APP11 security.

Q: GDPR’s purpose limitation? State a specified, explicit, legitimate purpose at collection; no incompatible further use → prevents scope creep.

Q: significance of accountability under GDPR + how to demonstrate compliance? Not only comply but be able to demonstrate it: records of processing (>250 staff must document) / appoint a DPO / training & review. Fines €10M/2% or €20M/4%.

Must know — GDPR 7 principles: lawfulness-fairness-transparency · purpose limitation · data minimisation · accuracy · storage limitation · integrity&confidentiality · accountability. Controller (sets purpose) vs Processor (acts on instructions); SAR answered within one month.

Wk10 · Cloud & Edge

Q: key characteristics that define cloud computing? shared pool of resources · over internet · on-demand (elasticity) · measured/pay-as-you-go · cost-effective. (elasticity ≠ resource multiplexing)

Q: public vs private vs hybrid?

Public Private Hybrid
Users public single org mix
Owner third party the org public+private
Trait low cost/scalable control/more secure portability (hospital)

Q: IaaS/PaaS/SaaS + an example each? Control spectrum (how far the user manages): IaaS = manage the OS (EC2) · PaaS = manage code (App Engine) · SaaS = manage only data (Gmail).

Q: motivation behind edge computing + how it complements cloud? Data centres are too far → latency (light travels ~300km in 1ms) → edge node processes nearby; latency-sensitive handled at edge / low-priority sent to cloud for deep analysis.

Q: common edge security risks + best practices? Risks: weak physical security / default-weak passwords / expanded IT perimeter / local credentials reach back to the data centre. Practice: treat the edge like a public cloud = zero trust + strong auth + encryption + monitoring.

Wk11 · TPM/Enclave/CPS/SCADA

Q: why is SCADA security critical + common threats? SCADA controls industrial processes (power/water), two tiers = management + PLC; a breach causes physical disaster (blackout/no water). Threats: hackers/malware/terrorists/insiders. Stuxnet = damaged Iran’s nuclear centrifuges (Siemens PLC).

Q: purpose of Secure Enclave, how it protects data? A TEE implementation, isolated region inside the main processor (OS can’t see it) → confidentiality + integrity: hardware isolation + memory encryption + UID (per-device, never leaves chip) + attestation = confidential computing (protects data in use).

Q: main differences between CPS and IoT?

IoT CPS
Core interconnection real-time control
Nature connect many devices self-contained system (car/drone)
Arch horizontal vertical
Connectivity core goal important, not mandatory

Q: what is a TPM, how does it enhance hardware security? TPM = on-board security chip storing keys/certs/passwords; hardware-based crypto (key never leaves chip) + measured boot (config altered → refuse to release key = attestation). TPM 2.0 = RSA + SHA256 + HMAC; use case BitLocker.

Core distinction: authentication (who are you) vs attestation (are you trustworthy now / config unaltered). Data states at rest / in transit / in use.

Wk12 · InfoWar/Cyberweapon/CCI/APT

Q: what is information warfare, how do attacks on critical infra fit in? Denning (broad: incl. propaganda/espionage/electronic warfare) vs Waltz (military: protection + denial). Hitting critical infrastructure (power) = mass disruption without firing a shot, a prelude to war (cyber-physical convergence).

Q: define a cyberweapon, how it differs from malware? Watershed = selectivity:

Cyberweapon Malware
Selectivity high (targeted) low (broad)
Actor state/non-state criminals
Motive strategic (military/political) profit
Example Stuxnet/NotPetya botnet

Four dangers: hard to trace / zero-day dormancy / cost asymmetry / captured & reused (EternalBlue).

Q: what is an APT + common motivations? APT = high expertise + significant resources + multiple vectors, builds a foothold and persists (state-sponsored / persistence / stealth). 6 stages: Recon→Delivery→Initial intrusion→C2→Lateral movement→Exfiltration. Motives = espionage / sabotage (not profit). E.g. Stuxnet (sabotage)/Duqu (recon)/Flame (espionage).

CCI = defensive in aim, offensive in method: defensive pen-testing→vulnerability assessment→threat intelligence→threat hunting; offensive honeypots/sockpuppets.
